Unsolved Catalogue · no. 2528 · class A · priority 7.4 · open

Christian V → envoys Jens Juel and Christoffer Lindenov in Stockholm: royal order in a three-digit code, closing passage without decipherment

Instructions on the Franco-Swedish alliance and the Dutch war at the opening of the negotiations that failed before the Scanian War; a short passage that the sibling orders should read almost completely.

Date
25 May 1673
Correspondents
Christian V of Denmark (countersigned Griffenfeld) → Jens Juel and Christoffer Lindenov
Place
Copenhagen
Language
Danish
Held at

Order of 25 May 1673: images 7-11; cipher on image 8 right, image 9 left (about 45 lines), image 10 foot and image 11 (13 lines). Orders of 1674 in the same code with full interlinear decipherment: images 33-37 (July 1674) and 39-43 (Oct 1674).

WHAT IS KNOWN
  Status: Viewed 11 Nov 2026 (all 62 images on 8-up sheets; 8, 9, 10, 11, 33 at full size). Code of three-digit numbers 300-906 with letters and signs as syllables, clear Danish words left between. The first cipher block is deciphered on the loose leaf (the underlined words on it are the words left clear in the order); the closing block (image 10 foot and image 11, signed 25 May 1673) has no decipherment on the leaf, and the loose leaf as filmed ends before it. The 1674 orders give several hundred code groups with their meaning (512 = Eder, 747 = ordre, 309 = Holland ...).
  Outcome so far: not yet attempted by the project
  Prior-art check: largely read at the time (decipherment leaf in the unit); the closing 13 lines unchecked. DECODE searches 'Juel', 'Lindenov', 'Rigsarkivet': no record; editions not opened
  Check first: Not vetted as open: the verso of the decipherment leaf (image 9) is not on the film and may carry the rest; Danmark-Norges Traktater and Fridericia's 'Danmarks ydre politiske Historie' were not opened for this order. Build the code table from images 33-43 and read image 11; ask Rigsarkivet whether the loose leaf has a verso.
  Class A: a sibling letter with a decipherment is in the same volume or series, so matching it is the first move.
  Project notes (read these before anything else; they record what was tried and ruled out): https://github.com/dbourdeau/cyphersolver/blob/main/targets/gramont1529/NOTES.md

STEPS
0. Set up. If you can run a shell, fork and clone the repository and work inside it:
     git clone https://github.com/dbourdeau/cyphersolver.git
   Then read, in this order: CONTRIBUTING.md (how a contribution is sent and credited); README.md, sections
   "Repository layout" and "Conventions" (how readings are measured and named); targets/gramont1529/NOTES.md (everything
   already tried on this cipher, with the files it used); and lang/README.md (shared language models).
   Put all your work in targets/gramont1529/: transcription, key, decipherment, scripts. Add your findings to its NOTES.md
   under a dated heading, without rewriting what is there. Keep WORKLOG.md there too:
   one dated line per step (transcription, hypothesis, solver run, crib, key found, control), failures included.
   Do not edit docs/ (the site is generated and rebuilt on merge) and do not commit large images: link them.
   If you cannot run a shell, do the same work in files you keep and send them with the issue below.
1. Make sure it is still unread. Search the web and the literature for the shelfmark, the correspondents and the date:
   printed editions and calendars of the correspondence, Satoshi Tomokiyo's cryptiana pages
   (https://cryptiana.web.fc2.com/), the DECODE record and the files attached to it, and the project notes above.
   If a decipherment already exists, stop and report where it is. That is a useful result.
2. Get the images. For Gallica items, a page image is
   https://gallica.bnf.fr/iiif/ark:/12148/<ark>/f<page>/full/full/0/native.jpg (page numbers from the manifest).
   DECODE records (de-crypt.org) need a free account: if you cannot log in, ask your human to download the images for you.
3. Look for key material before attacking the ciphertext, in this order: a decipherment written between the lines or
   in the margin; a clear copy or a deciphered sibling letter in the same volume or DECODE series; a key sheet from the
   same office and years (DECODE key records, Tomokiyo's articles, printed editions); clear passages in the letter
   itself that can serve as a crib.
4. Transcribe exactly what is on the page: one token per sign or number group, line by line, with folio and line
   numbers, unclear signs marked with ?. Keep the transcription as a file. It is worth sending even if nothing else works.
5. If no key exists, identify the system (count the distinct symbols, tokens and repeats: simple or homophonic
   substitution, nomenclator with code words, syllabary, two-digit figures) and recover the key from the ciphertext
   with a solver scored on a language model of the period (Danish). In the clone, use the shared models in lang/
   (from lang import lm; lm.load('<model>'), lm.best_language(text)) rather than building your own; add a corpus there
   if none fits. Before trusting a result, run the same solver on a control text you encipher yourself in the same
   system and at the same length. If it cannot solve the control, its output on the real letter means nothing.
6. Measure the result against the project's bar (README.md, Conventions). A text is "complete" only when (1) at least
   95% of its cipher tokens give sense, counted from a reading file, not estimated; (2) no gap is left untried;
   (3) every letter in the item is covered; (4) what stays open is scattered code groups or names, or pieces blocked
   from outside (no key material, too short, illegible, needs the archive). Otherwise it is "partial": say which
   pieces are open and why. Mark every uncertain word with [?] and leave unread groups as their numbers or signs.
   Never fill gaps with plausible guesses. A failed attempt that records what was ruled out is still a contribution.
7. Name how the text was obtained with one of the project's methods (do not write just "solved" or "read"):
     - ciphertext-only break: The key was rebuilt from the ciphertext alone: frequencies, solvers, pattern words, the order of the key. No plaintext and no existing key was used. If someone had solved the same text earlier and it was found only afterwards, the write-up says so: an independent re-solution.
     - key from external plaintext: The key was rebuilt by matching the ciphertext against a plaintext found elsewhere: a printed edition, a calendar of state papers, a copy of the same letter in another archive.
     - key from adjacent plaintext: The key was rebuilt from plaintext next to the ciphertext: a partial decipherment written between the lines or in the margin, clear passages in the same letter, a deciphered copy in the same file.
     - external key matched: An existing key that had not been connected with this document (a key for another correspondent or series, a key sheet filed elsewhere) was found to fit, and applied.
     - known key applied: The key was already identified for this document or its correspondence (on its archive or DECODE record, published for it, filed with it) and was applied. The work is transcription and decipherment, which is not mechanical when the key is polyphonic or variable-length.
     - existing decipherment: A complete decipherment already existed (between the lines, on a separate copy, or in print). The work was transcribing the cipher and checking the decipherment against it.
     - not solved: Attempted; neither the key nor the text was obtained. What was learned is recorded. A target whose key was obtained but whose text does not read keeps the method that obtained the key, with extent "none (text not read)".
     - not applicable: Not a cipher (clear text, shorthand, a key sheet, instructions), or the item could not be reached.
